# AGENTS.md

Instructions for agents and contributors working in this repository.

## Read first

1. `NOTICE` - the GPL boundary, the firmware rule and the proprietary blob.
2. `README.md` - layer boundaries and the board transport contract.
3. `FtsProtocol.h` - the wire contract.

## Hard rules

- **Do not copy code, comments, tables or data from the GPL-2.0 vendor driver.**
  The vendor tree is a behavioural reference only. Re-derive protocol facts and
  write the implementation in your own words. If a change needs a vendor table,
  express the facts as constants and explain the source in a comment.
- **Never add firmware** other than `firmware/focaltech_ts_fw_xinli.bin`. No
  extra `.bin` files, no generated byte arrays, no base64 blobs. Firmware reaches
  the probe through the weak `fts_board_firmware` symbols, which the board
  defines at build time.
- **Do not add GPL, BSD or vendor-licensed files** to this repository. The
  project is MIT.
- **Keep `FtsProtocol`, `FtsTouchCore` and `FtsHid` portable.** They must build
  with `-std=c99 -Wall -Wextra -Werror -pedantic` and must not include XNU or
  IOKit headers. XNU-specific code belongs in `FtsProbe.cpp`.
- **Do not claim hardware validation** unless someone actually ran it on a
  merlinx and recorded the result. Host tests are not hardware tests.
- **Do not commit unless the user asks.** Leave working-tree changes visible.

## Layout

- `FtsProtocol.[ch]`: package framing, status polling, CRC, registers,
  identification, power, report decode, firmware check/ECC/download.
- `FtsTouchCore.[ch]`: one slot per hardware contact id, down/up/active masks,
  missing-contact release, coordinate mapping.
- `FtsHid.[ch]`: seqlock publication for the board's HID source.
- `FtsBoard.h`: merlinx devicetree facts and the default core configuration.
- `FtsProbe.cpp`: staged XNU probe, weak board transport, frame loop,
  suspend/resume, diagnostic page.
- `Test/`: host tests for the three portable layers.

## Style

- C99 in the portable layers; C++11-or-later in `FtsProbe.cpp`.
- Four spaces, no tabs. Braces on the same line as the statement.
- `/* ... */` is not used; comments are `//`.
- Prefer explicit casts at type-width boundaries.
- Keep error paths explicit and return `FTS_ERR_*` values.
- Comments should explain a decision or a hardware fact, not restate the code.

## Testing

Always run:

```sh
./Test/run.sh
```

Expected output:

```
fts-protocol: ok
touch-core: ok
fts-hid: ok
```

When changing protocol framing or report layout, add or update a fake-bus case in
`Test/fts-protocol.c`. When changing slot lifecycle or mapping, update
`Test/touch-core.c`. When changing the snapshot ABI, update `Test/fts-hid.c`.

## Board changes

`FtsBoard.h` values must carry the devicetree source in a comment. Do not guess
GPIO polarity, bus number, chip select or panel orientation. If a value is
unknown, leave it out or document the uncertainty; do not invent a default.

`FtsProbe.cpp` must remain a thin consumer of the board transport. Do not grow
it into a MediaTek SPI, GPIO or clock driver.

## Review checklist

- Portable layers still compile with the strict flags above.
- No new XNU includes outside `FtsProbe.cpp`.
- No new firmware, no GPL text, no vendor source beyond the single image in
  `firmware/`.
- `NOTICE` and `README.md` still describe the code accurately.
- Tests pass.
